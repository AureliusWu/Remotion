# 视频制作与工程验证记录

每次视频制作都作为工程测试：记录可复现问题、修复与验证，再保留可复用工具。
默认先完成 Studio 预览；是否已导出整段成片单独说明。

## 2026-10-29：中国生成式 AI 用户规模

合成：`ChinaGenAiTimeline`。1920×1080、60 fps、3600 帧，严格 60 秒。
六个独立分镜时长为 10 / 14 / 10 / 8 / 10 / 8 秒，配六段本地中文旁白。

### 问题与修复

| 问题 | 原因 | 处理与验证 |
| --- | --- | --- |
| ESLint 报特殊空白字符 | 中文排版混入 U+3000 全角空白 | 用正常空格和 CSS 字距排版；ESLint、TypeScript 通过 |
| 后三段旁白初版语速偏快 | 为塞进固定时长，自动选择语速曾达到 5–6 | 精简文案，生成器限制语速上限为 4，过长时明确失败；六段最终语速 3 / 4 / 1 / 0 / 3 / 4 |
| 文案需同时区分“最新”和“今天” | 最新报告统计到 2026 上半年，公开日与检索日不同 | 全片明确统计期，片尾列检索日；保留“突破7亿”下限，不做实时插值 |
| 历史普及率存在 0.1 个百分点披露差异 | 不同官方报告对同一基期的披露未完全对齐 | 人数主图保留原始公开节点，不自行纠正百分比；来源文件解释限制 |
| 开篇问题与大数字间距不足 | 两行标题的行高和下方数字区共享空间 | 缩小标题行高并调整间距；1080p 静帧逐页目视检查通过 |

### 实际验证

- `npm run lint`：ESLint、TypeScript 通过。
- `npm run check:versions`：Remotion 配套包全为 4.0.539，Zod 4.5.4，无版本差异。
- `npm run build`：打包通过。
- `npm run verify:genai`：真实打包一次、读取 Chromium 合成元数据，确认
  1920×1080 / 60 fps / 3600 帧；静帧 180、1080、1740、2220、2820、3420、3599
  均生成 1080p PNG，记录 SHA-256。
- 六段 MP3 均通过 FFmpeg 完整解码；用 FFprobe 实测时长，延迟 0.6 秒后均未超出场景，
  最小尾部余量约 0.910 秒。音频清单与实际文件时长相符。
- Studio 元数据与自动验证一致；实际播放无错误覆盖层。读取 Studio 的真实时间轴，确认
  场景覆盖 0–3599 帧且无间隙；六段音频分别从 36、636、1476、2076、2556、3156 帧开始。
  连续观察约 68.8 秒后仍正常播放，已循环到第 544 帧，错误查询为 `null`；状态与实际
  时间轴保存在 `examples/china-genai/studio-validation.json`。
- 验证器负例：故意按 5 秒检查实际 6 秒的 `SmokeTest`，正确拒绝
  `durationInFrames: expected 150, got 180`，退出码为 1。

本轮交付是带旁白的可播放 Studio 合成及静帧，**未执行整段 MP4 导出**。
静帧检查、音频解码和预览成功不替代完整成片导出验证。
自动验证报告保存在 `video/out/ChinaGenAiTimeline-validation/report.json`，随本次作品保存
副本到 `examples/china-genai/validation.json`。

### 本轮沉淀

1. 新增通用 `video/scripts/verify-composition.mjs`，一次打包复用 Chromium 验证多个关键帧，
   输出规格、哈希、浏览器错误和音频余量；`npm run verify:genai` 提供本片入口。
   当前带旁白的校验使用 Windows 随工程附带的 FFmpeg/FFprobe 路径。
2. 新增 `video/scripts/generate-genai-voiceover.ps1`，使用已安装的 Huihui 中文声线本地生成，
   不需外部服务；记录文案、语速、时长，保留编码尾帧余量。Windows PowerShell 脚本采用
   UTF-8 BOM，供 Node 读取的 JSON 则使用无 BOM UTF-8。
3. 场景、数据、样式与时间轴拆分；每个分镜作为单独合成注册，编辑时可单独打开。
4. 信息图的数值与图形一起保留不确定性：下限柱使用虚线和上箭头，半圆图注明 50% 下限。
5. 将用户的“每次制作都测试、问题及时修复、经验及时沉淀”要求写入仓库 `AGENTS.md`，
   后续制作沿用该工作方式。

## 2026-10-29：等待与偶遇——泊松过程

本轮用户明确要求完成后导出 MP4。合成 `PoissonEncounters`：1920×1080、60 fps、
10800 帧，180 秒。九个独立场景，各 20 秒；九段中文旁白、36 条内嵌逐句字幕和原创轻音乐。

### 制作中修复的问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 初版多段旁白超过 18.4 秒 | 公式解释与人文文案较长，逐句合成还包含停顿 | 精简唯一源 `storyboard.json`，不截句、不提高到超过 3 的语速；重生成后全段符合预算 |
| 一句历史旁白有否定范围歧义 | “这不等于……，当时就已……”容易被听成后一分句的肯定 | 改为“这并不意味着，现代泊松过程在当时已经完整成形”；同步音频和字幕，主动终止旧渲染并重导 |
| 计数轨迹可能挤到上方事件轴 | 固定种子在 3 分钟中产生 9 次，初版纵向步高过大 | 重新安排阶梯纵向尺度和 N(t) 标签，关键帧检查确认两块图解分离 |
| 工程附带 FFmpeg 没有 `volumedetect` | 当前精简构建缺少该滤镜 | 完整解码到 PCM，按采样计算 RMS 与峰值，不增装来路不明的二进制 |
| MP3 容器包含编码补齐 | 180 秒音乐的容器时长约 180.036 秒 | 主时间轴显式裁为 10800 帧并淡出；旁白留出起播和尾部余量，避免被截句 |
| 成片完整解码检查首次报编码器缺失 | 工程 FFmpeg 未包含 null 输出默认选择的 wrapped_avframe | 验证器显式指定 rawvideo / pcm_s16le 后完整解码通过；未改动成片，也未安装额外二进制 |
| 导出音量检查的裸 PCM 容器不可用 | 工程 FFmpeg 未包含 s16le muxer | 改用支持的 WAV 容器承载 pcm_s16le，再读取 RIFF 数据块计算逐场音量 |

### 本轮验证与可复用能力

- `npm run lint`、`npm run check:versions`、`npm run build` 通过；依赖仍为 Remotion
  4.0.539 配套包与 Zod 4.5.4，没有改动上游检查器。
- `npm run verify:poisson` 通过：真实合成规格为 1920×1080 / 60 fps / 10800 帧，
  检查帧 600、2100、3300、4500、5700、6900、8100、9300、10500、10799。
- 九段旁白完整解码通过，单段 ≤18.4 秒、语速 ≤3，从每场 0.7 秒开始。字幕按逐句 PCM
  采样长度生成，间隔约 0.22 秒，额外保留约 0.15 秒阅读时间；36 条均无重叠、无越界。
- 纯本地、固定音符合成原创音乐；音乐 RMS 至少低于最轻旁白 25.29 dB，所有音频源峰值
  低于 0 dBFS。音乐清单用 SHA-256 绑定本次旁白清单。
- 数学审查：P(N(1)=0)=P(T>1)=exp(−2)≈13.5335%；平均等待为 30 秒；无记忆对照
  的两项尾概率均为 exp(−1)≈36.7879%。模拟、示意及历史书封重绘均在画面标注。
- 通用合成验证器新增字幕时码、重叠、边界与音频流检查；旧入口 `npm run verify:genai`
  回归通过。
- 新增 `scripts/verify-export.mjs`：对实际 MP4 检查 H.264/AAC、1080p、帧率、总帧数、
  音视频时长，并完整解码和计算 SHA-256。它验证的是成片文件，不把源码规格当作导出证据。

数学来源与完整内容结构见 [POISSON-FILM.md](POISSON-FILM.md)。
本轮成片实际元数据与完整解码结果保存于 `examples/poisson-process/export-validation.json`；
预渲染抽样报告保存于同目录 `composition-validation.json`。
